Introduction

The National Football League (NFL) has 14 official positions for players: 7 offensive, 5 defensive, and 2 special teams positions. One of the offensive positions is the quarterback (QB), whose primary role is to lead the offense on the field. ESPN provides a lot of data on NFL games and players, including the Total Quarterback Rating (QBR), a metric on a scale from 0 to 100 that estimates a quarterback’s overall contribution to winning. Higher QBR values indicate better performance.

In this module, you will learn how to predict Total Quarterback Rating using game-level data from the 2025 NFL Regular season. To predict QBR, we will use stepwise regression, and you will have the option to complete the analysis in R, Python, or Julia. After selecting the best model with stepwise regression, we will use quantile analysis to see which quantile of quarterbacks (e.g. the top 10%, bottom 10%, etc.) are best explained by the selected model.

To complete the regression analysis, we will use the programming environment Visual Studio Code (VS Code). VS Code is very popular both in academic and industry settings, making it a valuable tool to become familiar with. One of the biggest advantages of using VS Code is that it supports multiple programming languages within a single interface, allowing you to work in R, Python, or Julia without switching environments.

Data Source

The data was scraped from ESPN’s NFL statistics pages using the R package nflreadr. The dataset was created using the nflreadr functions load_espn_qbr(2025, summary_type = "week"), load_schedules(2025), and load_player_stats(2025, summary_level = "week"), which provided weekly quarterback ratings, game information, and player performance statistics from the 2025 NFL regular season.

After cleaning and joining the data sources, the final dataset included only quarterbacks who appeared in a regular season game during the 2025 NFL season. Each row in the dataset represents a single quarterback’s performance for one game during a specific week of the season.

Stepwise Regression

Stepwise regression helps find a useful combination of predictors for explaining a response variable by testing different combinations of predictors. For example, if we want to predict someone’s height, we might start with a dataset that includes height, age, sex, number of apples eaten a year, and full name. Stepwise regression looks at different combinations of the other variables and keeps the ones that help predict height the most.

The first step is to identify the variables that could reasonably help predict the response. For our dataset, the player statistics variables describe the quarterback’s performance in each game, and the game details variables describe the conditions surrounding the game that can affect performance. If you are not sure what a variable means, check the descriptions in the data section. If a variable seems like it might help, you can include it as a candidate predictor and let stepwise regression decide whether to keep it. A candidate predictor is a variable that is being considered as a candidate for being a predictor in our final model due to its potential to predict QBR.

It can be helpful to store the predictors in a vector so that you can easily add or remove variables while cleaning your data. For example, if a dataset included height, age, sex, apples_eaten_yearly, and name, you could store the variables you think might help predict height like this:

predictors <- c("age", "sex", "apples_eaten_yearly")

Notice that full name was left out because it is only an identifier and does not help explain height. We also leave out height itself because that is the response variable we are trying to predict.

Before we can use stepwise regression, we first fit a full linear model. A full linear model includes all of the candidate predictors we want to consider, so it gives us a starting point before stepwise regression begins removing or keeping variables.

If we made a full linear regression model to predict height using the imaginary data mentioned earlier, it would look something like this:

full_mod <- lm(height ~ ., data = height_dataset[, c("height", predictors)])

We use height ~ . to tell the model to use all of the other variables from the data as predictors of height. Then we give the model only the variables we want it to use, including height and the predictors we selected.

full_mod <- lm(qbr ~ ., data = nfl_qbr[, c("qbr", predictors)])

Now that we have fit a full linear regression model, we are ready to start stepwise regression. Stepwise regression is a way to find the best combination of predictors by adding or removing predictors one at a time. In forward selection, the model starts with no predictors and adds variables that improve the model. In backward elimination, the model starts with all predictors and removes variables that do not help much. In both directions, the model can add or remove predictors until it finds a better combination.

In this module, we use both forward and backward stepwise regression. That means the model starts with the full model, but it is also allowed to remove weak predictors and add back useful ones if needed.

For example, if we were predicting height from age, sex, and number of apples eaten a year, stepwise regression might start with all three variables, remove the number of apples eaten a year if it does not help, and keep age and sex if they improve the model. Using the stepAIC() function from the MASS package that we loaded in, that would look something like this:

step_mod <- stepAIC(full_mod, direction = "both")
summary(step_mod)

The stepAIC() function searches for a smaller model with a lower AIC value. AIC is a number that helps compare models by balancing how well they fit the data with how simple they are, so a lower AIC usually means a better model. In this case, direction = "both", means the function can try adding predictors, removing predictors, or doing both as it searches for the best model.

An important part of building a model is checking how well it performs. This helps us understand whether the model is doing a good job predicting the response variable. For stepwise regression, we can use the adjusted R-squared value in the model summary to measure how much of the variation in QBR is explained by the model. In general, values closer to 1 indicate a better fit to the data.

We can also use the model summary to identify which predictors are especially useful for explaining QBR. The Pr(>|t|) column contains p-values that measure whether each predictor is significantly related to the response variable. In the output, significant predictors are marked with asterisks (*). More asterisks indicate stronger statistical significance. The smaller the predictor’s p-value is, the stronger it is associated with QBR in the model.

Quantile Regression

Quantile regression helps us study different parts of the response variable instead of only the average. A quantile is a point that splits the data into groups, like the 10th percentile, 25th percentile, or 50th percentile.

Similar to how we made a vector of predictors, we can make a vector of quantile values. For example:

quantiles <- c(0.2, 0.4, 0.6)

This would represent the 20th, 40th, and 60th percentiles. A weekly QBR at the 20th percentile would be a higher QBR than 20% of all weekly QBR values and lower than 80% of them.

NoteExercise 6: Set Quantiles

Create a vector named quantiles that includes the 10th, 25th, 50th, 75th, and 90th percentiles.

Click for Solution 
quantiles <- c(0.1, 0.25, 0.50, 0.75, 0.90)

Now that we have a vector with all the quantiles we are interested in, we need to fit a quantile regression model for each value in the vector. We do this using the rq() function in the quantreg package for linear quantile regression and the map() function from purrr package in tidyverse to fit a model for each quantile. Using our imaginary height dataset, it would look like this:

qr_models <- map(quantiles, ~ rq(height ~ age + sex, tau = .x, data = height_dataset))

We use tau = .x to set tau to every value in the list of quantiles we give it and we use the equation given to use by stepwise regression, so for this example age + sex, leaving out apples_eaten_yearly.

Quantile regression doesn’t use the usual “squared error” from linear regression, so we can’t use regular R-squared to measure how well the model fits. Instead, we use something called pinball loss (also known as quantile loss) to see how close our predicted quantiles are to the real data. Pinball loss penalizes predicting QBR too high or too low differently depending on what quantile you are predicting for. For example, for the 10th percentile, being too high would be penalized more than being too low.

Here’s an example of how to calculate it, copy and paste the following code into your R document to evaluate our selected model to see how accurately it predicts QBR for different quantiles:

# Compute pinball loss for a quantile regression model
qr_pinball <- function(model, data, response, tau) {
  y <- data[[response]]
  y_hat <- predict(model, newdata = data)
  
  loss <- ifelse(y >= y_hat,
                 tau * (y - y_hat),
                 (1 - tau) * (y_hat - y))
  
  mean(loss)}

# Table of pinball loss for each quantile model
qr_pinball_table <- map_dfr(seq_along(qr_models), ~ {
  tibble(
    quantile = quantiles[.x],
    pinball_loss = qr_pinball(qr_models[[.x]], nfl_qbr, "qbr", quantiles[.x]))})
