Background

The World Kung Fu Championships (WKFC), hosted by the International Wushu Federation (IWUF), is an international level sporting event established in 2004 to propagate the development of wushu around the world. As there are dozens of Kung Fu (traditional wushu) styles represented in the WKFC, these championships offer a unique platform for thousands of practitioners of all ages and varying skill levels to come together every two years.

Scraping

Data scraping is the activity of taking information from a website or computer screen and putting it into an ordered document on a computer1.

1 Cambridge Dictionary. “Data Scraping.” @CambridgeWords, 12 Feb. 2025, dictionary.cambridge.org/us/ dictionary/english/data-scraping.

The process of scraping data can look very different depending on the format the data is originally being sourced from, the ideal end result or format of the scraping process, and the chosen scraping method. Most understandably, it can be natural to assume that the source and goal will dictate the method, however this is a flexible process and preference is welcome.

Since the source in this case is a pdf file, and the goal a csv file, the scraping method was via Adobe Acrobat Pro. This program has excellent reading functionalities that allow field detection for text export.

Once the desired information fields from the tables in the result book are selected for scraping, the program iteratively goes through each page selecting the chosen fields and exporting the information into columns of a table of a csv spreadsheet.

The same general process was repeated for each one of the four result books from 7th to 10th edition.

Cleaning Data

The process of cleaning data involves a fundamental understanding of the nature fo the variables and what they are meant to represent, in order to avoid overwriting or editing important information that modifies the integrity of the data.

Afterwards, it is imperative to have a goal presentation for the data. This is a very nuanced process that changes drastically depending on the type of data, the method used to clean it and of course the goal.

Notepad++

Notepad++ was used as a supplementary tool for intermediate text preprocessing, particularly in stages where bulk string manipulation was more efficiently handled outside of R or Excel. The goal was not to replace these environments, but to streamline operations that are cumbersome when working within cell-based or syntax-constrained systems.

The workflow involved temporarily exporting individual columns from Excel into Notepad++, performing targeted text transformations, and reinserting the cleaned output back into Excel while preserving the original row order. This approach ensured that no observations were lost or misaligned during the process.

Notepad++ proved especially useful for operations that require direct manipulation of raw text, including:

  • Line operations (e.g., removing or duplicating specific rows)
  • Blank/whitespace management (e.g., deleting empty lines or trimming irregular spacing)
  • Global find-and-replace with extended search modes (including regex support)

A key advantage of Notepad++ is its support for column-mode (multi-cursor) editing, which allows simultaneous modification across multiple lines at the same character position. This functionality enables efficient correction of systematic formatting issues that would be difficult to address in Excel, where edits are typically confined to individual cells.

It is important to note that many of these transformations are technically achievable in R or Excel. However, Excel lacks native support for regular expressions and multi-line text editing, and while R provides powerful string-processing capabilities, it may be less efficient for rapid, exploratory cleanup of visibly inconsistent text. In this context, Notepad++ serves as a practical intermediary for quick, low-overhead preprocessing.

Within Excel, its strengths were leveraged for complementary tasks such as filtering, sorting, and basic data validation. For instance, filtering was used to identify missing values (NAs), while sorting facilitated the detection of duplicate or inconsistently labeled entries.

The work on Notepad++ was then completed using RStudio.

RStudio

The data cleaning process in RStudio relied primarily on structured string parsing using regular expressions (regex). Given that the raw data consisted of concatenated textual fields, a pattern-based extraction approach was more appropriate than positional or delimiter-based splitting. Regex enables the identification and extraction of semantically meaningful components within strings, making it particularly well-suited for this task.

A key principle guiding this process was to avoid reliance on character position or incidental formatting (e.g., capitalization or spacing), and instead leverage consistent structural markers embedded in the data.

NoteExample

Consider the string:

“International Women’s Group C Traditional Chen Style Taijiquan”

This information appears as a single string following data scraping and must be separated into three variables:

  • The sex of the athlete
  • The age group of the athlete
  • The Kung Fu form

There are multiple valid approaches to this problem. Evaluating alternative strategies before implementation is a useful practice, as different methods may vary in efficiency.

Rather than extracting these components iteratively or positionally, we exploit the inherent structure of the string. Specifically:

  1. The sex is encoded as either “Women’s” or “Men’s”
  2. The age group is explicitly labeled as “Group X”, where X ∈ {A, B, C, D, E, F}
  3. The form corresponds to all text following the group label

This structure allows us to define a single regex pattern with capture groups that extract all variables simultaneously.

A suitable pattern is:

  1. (Women’s|Men’s) → captures the sex
  2. Group ([A-F]) → captures the group letter
  3. Group [A-F] (.*) → captures the remaining text as the form

Using functions such as extract() from the tidyr package or separate_wider_regex(), we can implement this in a single step, ensuring both efficiency and reproducibility.

This approach has several advantages:

  • Robustness: It relies on semantic labels rather than positional assumptions
  • Scalability: It generalizes well to larger datasets with consistent structure
  • Clarity: The extraction logic is transparent and directly interpretable

Following extraction, minor post-processing steps (e.g., trimming whitespace or standardizing labels) can be applied to finalize the dataset.

While alternative approaches such as iterative substring removal or delimiter-based splitting may yield correct results in specific cases, they are generally less robust and harder to justify in a formal data processing pipeline.

Regex-based extraction provides a more principled and reproducible solution, particularly when working with semi-structured textual data.

Regular expressions

A regular expression (regex for short) is a special text string for describing a search pattern.2 These expressions are very useful to identify a specific pattern in text. An example of regular expression used to clean up some of the strings in the WKFC data is:

2 Regular-Expressions.info - Regex Tutorial, Examples and Reference - Regexp Patterns. Www.regular-Expressions.info, www.regular-expressions.info.

^.*(?=.$)

This expression reads as “everything from the start of the string up to (but not including) the final character”, and it appears in the following code to remove all the information before the group-identifying letter A through D (exclusive to the 7th championship).

```{r}
sevenyear <- read.csv("7kf.csv") # reading the scraped data

sevenyearworking <- sevenyear |> 
  separate_wider_regex(Form, c(Delete = "^[^MW]*", Form = ".*")) |> 
  # Everything up to but not including the first "M" or "W" in the string
  # gets grouped for deletion in a "Delete" column.
  # The rest of the string gets sent to column "Form" for more edits.
  
  select (-Delete) |> # Eliminating "Delete" column
  
  separate_wider_regex(Form, c(Sex = "^[^G]*", Form = ".*")) |> 
  # Everything up to but not including the first "G" (Men or Women),
  # gets placed in column "Sex"
  # Everything else in the string stays in column "Form" for more edits.
  
  separate_wider_regex(Form, c(Group = "^[^A-Z]*[A-Z][^A-Z]*[A-Z]",
                               Form = ".*"), too_few = "align_start") |>
  # Everything up to but not including the second uppercase letter 
  # (including any characters before, between, and around them) 
  # goes to column "Group". This column includes more information to be erased.
  # The remainder of the string goes to column "Form" for more editing.
  
  na.omit(Form) |> # Remove missing cases in the "Form" column.
  
  separate_wider_regex(Sex, c(Sex = "^.", Delete = ".*")) |> 
  # From the "Sex" column made before,"we keep only the first character.
  # Everything else in the "Sex" column goes to "Delete" for elimination.
  select (-Delete) |> # Removing "-ens" and "omen's" from the "Sex" column.
  
  separate_wider_regex(Group, c(Delete = "^.*(?=.$)", Group = ".$")) |> 
  # Everything except the last character gets sent to "Delete" for elimination.
  # Column "Group" will include only the last character of the string.
  
  select (-Delete)
```

The argument too_few = "align_start" ensures that if a string doesn’t match enough parts to fill both outputs, the available text is aligned from the beginning rather than causing an error.

Our focus at this stage is the column Form

2. Step 1: Separate the Form column Goal: Separate strings in the Form column into 3 columns for Sex, Group and Form.

```{r}
first_step <- kf_8 |> 
  # The first character of the string in Form goes to column Sex
  # The rest of the string goes to Form for further edit
  separate_wider_regex(Form, c(Sex = "^.", Form = ".*")) |>
  
  # From the remainder of the string now in Form, we delete everything up to
  # the first capital G, everything else goes to column Group for further edit
  separate_wider_regex(Form, c(delete = "^[^G]*", Group = ".*")) |> 
  
  # Iterative deletion of unneeded parts of the string
  select (-delete)
```

Iterative deletion helps students see clearly which elements of the string are being removed.


Other, more efficient methods are also perfectly acceptable and recommended for processes like this. In practice, the method generally adapts to the type of data we are tasked with cleaning. Further, for cleaning strings, it is recommended to err on the clearer side, breaking down steps in case something has to be corrected or adjusted.

10th WKFC Data Cleaning

This section focuses on the iterative cleanup process of the data used for the SCORE module 2025 10th World Kung Fu Championship - Complete Linkage Hierarchical Clustering.

The first step of the cleaning process was therefore focused on systematically separating * Athlete sex
* Kung fu form category
* Competition group

fro the Form column into usable variables.

```{r}
kungfu<- read.csv("kungfu_data_dirty.csv")
head(kungfu, 25)
```

Step 1 — Removing Group Event Categories

Certain observations corresponded to group performance events (Duilian) rather than individual athlete performances. Since these events are structurally different from standard individual routines, they were removed prior to further cleaning and analysis.

At the same time, the first character of each string in the Form column was extracted in order to create a preliminary sex variable representing “Men’s” and “Women’s” categories.

```{r}
kungfu_strings <- kungfu |> select(-Page) |>
  filter(Form != "Bare-hand Duilian(2 Persons)", 
         Form != "Weapon Duilian(2 Persons)",
         Form != "Other Duilian") |>
  # Removing "duilian" events because that's a group event
  separate_wider_regex(Form, c(sex = "^.", Form = ".*"))
  # The Sex column with the first letter of the words "Men's" and "Women's"
```

Step 2 — Removing Prefix Text from Form Labels

After extracting the initial sex identifier, the remaining strings still contained unnecessary prefix text such as fragments from “Men’s” and “Women’s”.

Regular expression separation was therefore used to isolate the meaningful portion of the form description while discarding the leading text artifacts introduced during parsing.

```{r}
# this code gets rid of the end of "en's and "omen's"
getting_rid_of_up_to_form <- kungfu_strings |>
  separate_wider_regex(Form,
  patterns = c(
    delete = "^[^\\s]+",
    "\\s+",
    rest = ".*"))
```

Step 3 — Separating Form and Group Information

The remaining string still contained both the kung fu form name and the competition group designation.

To separate these variables, the cleaning process identified the first occurrence of the capital “G” in “Group” and split the string accordingly. This produced two independent variables: - Form - Group

This transformation converted the previously unstructured text field into analytically usable categorical variables.

```{r}
# this code creates the form column by selecting everything up to the capital G for "Group" and by doing that creates the column for Group

selecting_the_form <- getting_rid_of_up_to_form |>
  select(-delete) |>  separate_wider_regex(rest,
  patterns = c(
    Form = ".*?(?=G)", 
    Group = ".*"))
```

Step 4 — Final Corrected Dataset

At this stage, the remaining work consisted primarily of repairing missing or malformed group labels that were lost during the original parsing process of the result book.

The fully corrected and manually verified dataset was then re-imported as the finalized clean dataset kf.

```{r}
kf <- read.csv("kungfu.csv")
```

Step 5 — Removing Defaulted Athletes

Before conducting statistical analysis, athletes who defaulted from competition were removed. Observations with missing scores were also excluded.

Additionally, non-analytical columns such as ranking remarks and indexing variables were dropped.

```{r}
# the number of total athletes before removing defaulted athletes is 2129
sample_kungfu <- kf|> filter(Rank != "Default") |> drop_na(Score) |> select(-X, -Rank, -Remark)
# the number of athletes after removing defaulting athletes is 1989
# difference is 140 athletes.
```

The filtering process reduced the dataset from 2129 athletes to 1989 valid athlete observations.

Step 6 — Standardizing Form Names

One major issue in the parsed dataset involved inconsistent naming conventions for the same kung fu forms. Variations in capitalization, spelling, spacing, and terminology created duplicate categories that referred to identical events.

To resolve this, the fct_recode() function was used to standardize form labels into unified categories.

After recoding, the dataset was grouped by:

  • Group
  • standardized form labels (recoded_forms)

Mean scores were then calculated for each combination and reshaped into wide format for later analysis.

```{r}
usable_sample_kungfu <- read.csv("sample_kungfu.csv") |> 
  mutate(recoded_forms = fct_recode(Form,
  # Shanzi variations
  "Single weapon routines Shanzi (Fan)" = "Single weapon routines Shanzi (Fan)",
  "Single weapon routines Shanzi (Fan)" = "Single weapon routines shanzi",
  
  # Pudao variations
  "Single weapon routines Pudao" = "Single weapon routines Pudao",
  "Single weapon routines Pudao" = "Single weapon routines Pudao/Dadao",
  "Single weapon routines Pudao" = "Single weapon routines Pudao/Guandao (Kwan Dao)",
  "Single weapon routines Pudao" = "Single weapon routines Guandao /Pudao",
  "Single weapon routines Pudao" = "Single weapon routines Guandao (Kwan Dao)",
  
  # Weapon other variations
  "Other weapon routines" = "weapon Other routines",
  "Other weapon routines" = "weapon routines Other routines",
  
  # Bare hand other variations
  "Other bare hand routines" = "bare hand routines Other routines",
  "Other bare hand routines" = "Other bare hand routines ",
  "Other bare hand routines" = "bare hand routines Other routines",
  
  # Taiji weapon variations
  "Single weapon routines Other Taiji weapon" = "Single weapon routines Other taiji weapon",
  "Single weapon routines Other Taiji weapon" = "Single weapon routines Other Taiji weapon"
)) |> group_by(Group, recoded_forms) |> summarise(mean_score = mean(Score), .groups = "drop")|> pivot_wider(names_from = Group, values_from = mean_score)
```

Step 8 — Missing Data Imputation Using KNN

After cleaning and standardization, the dataset still contained missing values.

K-Nearest Neighbors (KNN) imputation was selected as the primary imputation method because the later analytical workflow involved clustering and similarity-based comparisons.

KNN imputes missing values by using observations with similar feature patterns, preserving local data structure more effectively than simple mean substitution.

```{r}
kf10_imp_knn <- kNN(usable_sample_kungfu, k = 5) |> select(-A_imp,-B_imp,-C_imp,-D_imp,-E_imp,-F_imp, -recoded_forms_imp) 
# You can adjust 'k' as needed
```

The function kNN comes from the VIM package, VIM stands for “Visualization and Imputation of Missing Values.”

This package provides methods for imputation and visualization of missing values. More detailed information about this useful package is available here.

Visualization of the Missingness

The viss_miss() function is a useful way to visualize the scale of missingness of the data. Prior to imputation, missing data patterns were visualized with this plot to assess the distribution and concentration of missing values across variables.

```{r}
mssing <- vis_miss(usable_sample_kungfu)
```

Multiple Imputation Using MICE is another of the many methods available to substitute missing values from incomplete data.

Multiple Imputation by Chained Equations (MICE) ‘fills in’ (imputes) missing data in a dataset through an iterative series of predictive models. In each iteration, each specified variable in the dataset is imputed using the other variables in the dataset. These iterations should be run until it appears that convergence has been met (Wilson, 2021).



Predictive Mean Matching (pmm()) is the procedure within MICE imputation that selects a data point from the original, nonmissing data which has a predicted value close to the predicted value of the missing sample. The closest N values are chosen as candidates, from which a value is chosen at random. More information about this useful algorithm is available online on the “The MICE Algorithm” by Sam Wilson.

Step 9 — Final KNN Imputation for Clustering Analysis

For the final clustering-oriented dataset, KNN imputation was again applied using k = 5.

The rationale for this approach is that clustering methods depend heavily on local similarity structures, making neighborhood-based imputation especially appropriate for preserving relational patterns within the data.

```{r}
library(VIM)

kf10_imputed <- kNN(kungfu_10, k = 5) |> select(-A_imp,-B_imp,-C_imp,-D_imp,-E_imp,-F_imp, -recoded_forms_imp)  # You can adjust 'k' as needed
```

Step 10 — Final Matrix

The fully cleaned and imputed matrix was exported for use in clustering, visualization, and downstream statistical analysis.

```{r}
write.csv(kf10_imputed, "matrix_kf10.csv")
```
